# matcher CI runner host

One dedicated Linode that runs the heavy GitHub Actions jobs of the **private** `Decentral-America/matcher` repository (dex-it shards, dex-integration-it, image builds, unit tests, OWASP) on ephemeral self-hosted runners, so that repository spends almost no GitHub-hosted minutes. Nothing else may ever run on it.

| | |
|---|---|
| Code | `terraform/matcher-ci-runner.tf`, module `terraform/modules/matcher-ci-runner` (host files in its `files/`) |
| Linode | label `dcc-matcher-ci-runner`, `us-central` (same region as the VPS), `g6-dedicated-8`: 8 dedicated vCPU, 16 GB, 320 GB, **$144.00/month** ($0.216/h) |
| Runners | repository-level on matcher only, labels `self-hosted, Linux, X64, matcher-ci`, `MCI_SLOTS` (2) kept ready |
| Secrets | `secrets/matcher-ci-runner.env` (SOPS, testnet age key): `ops` SSH key, GitHub App credential |
| Monitoring | VPS Prometheus job `matcher-ci-runner` (node_exporter + runner metrics), alert group `matcher-ci` |
| Guard | `.github/workflows/self-hosted-runner-guard.yml` (no public repo may target the label) |

## How it works

```
precheck (GitHub-hosted, ~1 min)            runner host (Linode)
  reads MATCHER_CI_RUNNER_HEARTBEAT  <---- mci-heartbeat.sh every 2 min (while a runner is registered)
  self-hosted labels, or fail fast         matcher-ci-slot@1..N (systemd, Restart=always), per job:
        |                                    registration token -> docker run --runtime=sysbox-runc (new container,
        v                                    own dockerd on a NEW volume, 7 GB cap) -> config.sh --ephemeral -> one job
  heavy jobs on [self-hosted, matcher-ci]    -> container + volume deleted -> mci-verify-clean.sh -> next runner
```

* **Isolation per job.** Every job starts in a new sysbox container from `matcher-ci-runner:current` (Ubuntu 24.04 + Docker Engine + actions/runner). Its Docker daemon (testcontainers, the Kafka service container, image builds) lives in that container on a per-job volume. There is no host Docker socket in any job, no `--privileged`, and inter-container traffic on the host bridge is off (`icc=false`). After the job the slot removes the container and the volume and checks that nothing carrying the slot label is left (`matcher_ci_runner_slot_cleanup_failures_total`).
* **Network.** Cloud firewall and host nftables (`files/matcher-ci.nft.tmpl`): inbound SSH from `matcher_ci_runner_ssh_allowed_ips` only, `:9100` from the VPS only. Outbound DNS, NTP, HTTP, HTTPS only. Jobs cannot reach link-local (the Linode metadata service holds the host's user data), private or CGNAT ranges.
* **Host.** SSH key-only for `ops`, root login off, host key generated by tofu and pinned in `ssh/known_hosts` (no trust-on-first-use; it survives instance replacement). Unattended security upgrades daily, reboot at 07:30 UTC when required. Docker and sysbox are not auto-upgraded (a daemon restart kills running jobs).
* **Immutable.** The whole host is configured from user data at first boot (`files/install.sh`, every download pinned by version and SHA-256). Changing anything under `files/` replaces the instance on the next apply. The GitHub credential is never in user data; push it again after a replacement.
* **Runner version.** `matcher-ci-image.timer` rebuilds the image daily from the latest actions/runner release, verified against the SHA-256 GitHub publishes in the release notes (pinned fallback in `mci-image-build.sh`). Runners register with `--disableupdate`.

## Why the self-hosted runners can never run public-repository code

1. Runners are registered at **repository** level on `Decentral-America/matcher`. GitHub only assigns them jobs of that repository. (The org is on GitHub Free, which has no custom runner groups; repository registration is the stricter equivalent. The org's Default group also has `allows_public_repositories: false`.)
2. `self-hosted-runner-guard.yml` runs daily and on every infra change: it scans every public repository's workflows and fails on the `matcher-ci` label or `self-hosted` in `runs-on` (unit test: `scripts/tests/check-self-hosted-labels.test.sh`).
3. matcher is private; fork pull requests cannot run there.

## Provision / replace

1. Plan and apply through the normal path: `provision.yml` (`network=testnet`, `action=plan`, then `apply`). The plan must show only the runner resources and `linode_firewall.backend` (its egress rule to the runner's `:9100`).
2. Copy the `matcher_ci_runner_known_hosts` output into `ssh/known_hosts` (replacing the old line: the host key is the same, the IP changes on replacement).
3. Install the GitHub credential (below). Within 2 minutes `MATCHER_CI_RUNNER_HEARTBEAT` updates and matcher CI uses the host.
4. Run `Deploy Monitoring Stack` so Prometheus scrapes the new IP (`file_sd/matcher-ci-runner.json`).
5. Check: `ssh ops@<ip> 'systemctl is-active matcher-ci-firewall docker sysbox node-exporter matcher-ci-slot@1 matcher-ci-slot@2'` and the runners online under matcher Settings > Actions > Runners.

## GitHub credential

The host needs a token that can register runners on matcher (repository permission **Administration: read and write**) and update one repository variable (**Variables: read and write**). Preferred: a GitHub App owned by the org, installed on matcher only.

* **Create it once:** `scripts/matcher-ci-runner/create-github-app.sh`. It opens GitHub's App-manifest page with the permissions preset (click *Create*), then the install page (choose *Only select repositories* > matcher). It refuses an installation that covers anything but matcher, stores App ID, installation ID and private key in `secrets/matcher-ci-runner.env` (SOPS, never printed) and runs `push-credential.sh`. If GitHub rejects the preset `actions_variables` permission key, set *Variables: Read and write* on the App's permissions page and accept it on the installation.
* **Push it to a (new) host:** `scripts/matcher-ci-runner/push-credential.sh`.
* **Alternative:** a fine-grained PAT (resource owner Decentral-America, repository matcher only, the two permissions above) stored as `GITHUB_PAT` in the SOPS file, then `push-credential.sh`. It expires and is tied to a person; prefer the App.
* **Bootstrap only:** `scripts/matcher-ci-runner/bootstrap-registration-token.sh --loop` mints 1-hour registration tokens with the operator's `gh` login (they can register runners and nothing else) and sets the heartbeat variable from the operator machine. Used for the first verification before the App existed. Stop it once the App credential is installed.

## Fallback when the host is down

`precheck` fails the run within a minute with an explicit error instead of queueing jobs (a job for an offline self-hosted label waits up to 24 hours). Alerts: `MatcherCiRunnerDown`, `MatcherCiRunnerHeartbeatStale`, `MatcherCiRunnerSlotsDegraded`, `MatcherCiRunnerCleanupFailed`, `MatcherCiRunnerJobOomKilled`, `MatcherCiRunnerDiskLow` (GitHub issues via alert-webhook).

* **Run on GitHub-hosted runners** (spends minutes, ~245 per full run): `gh variable set MATCHER_CI_RUNNER -R Decentral-America/matcher --body github-hosted`, then re-run. `auto` = self-hosted when the heartbeat is fresh, else GitHub-hosted.
* **Back to self-hosted:** `gh variable delete MATCHER_CI_RUNNER -R Decentral-America/matcher` (unset means self-hosted).
* Deploy Matcher never blocks on the host: its gate uses `auto` unless the variable says otherwise, and its SSH deploy job always runs GitHub-hosted (production deploy keys never reach the host that runs pull-request code).

## Operations

| Task | Command (on the host as `ops`) |
|---|---|
| Runner logs | `sudo journalctl -u 'matcher-ci-slot@*' -f` |
| Slot state | `sudo ls /run/matcher-ci/`; `cat /var/lib/node_exporter/textfile/*.prom` |
| Prove a slot is clean | `sudo /opt/matcher-ci/mci-verify-clean.sh 1` |
| Rebuild the runner image now | `sudo systemctl start matcher-ci-image.service` |
| Change slot count / memory | edit `matcher_ci_runner_slots` / `_slot_memory` in `testnet.tfvars`, apply (replaces the host), push the credential |
| Docker / sysbox upgrade | apply with a bumped pin in `files/install.sh` (replacement), never `apt upgrade docker-ce` on a busy host |
| SSH from a new operator IP | add the CIDR to `matcher_ci_runner_ssh_allowed_ips`, apply (in place for the firewall; replaces the host because the nft allowlist is in user data) |

## Sizing and cost

Measured on this host (sysbox container per job, 7 GB cap): see the "Measured" table in `audits/2026-10-18/plans/CI-OPTIMIZATION-PLAN.md` (Done, absolute best). The plan is the smallest dedicated-CPU size that runs two dex-it shards at the GitHub-hosted runner's memory (7 GB) side by side with headroom; shared-CPU plans are rejected by the module because dex-it's historic failures were CPU starvation.

Cost: **$144.00/month** flat (Linode bills hourly up to the monthly cap; a powered-off Linode is still billed). The repository variable `MATCHER_CI_SHARDS` sets the dex-it shard count on this host.
